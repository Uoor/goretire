## 1. 模块结构（Maven multi-module）

```
backend/
├── pom.xml              # 父工程（聚合 core/houserent/app/test）
├── core/                # 基础设施纯库：common（统一响应/异常）+ auth（免登/JWT/UserContext）+ user + config + interceptor
├── houserent/           # 租房业务全部：house（房源）+ demand（求租）+ subscribe（订阅）+ match（LLM 匹配）+ admin（审核/举报）
├── app/                 # 应用入口：启动类 + application.yml + schema.sql（唯一可执行，exec fat jar）
└── test/                # 集中测试（依赖 app）
```

**模块边界约定**：
- `houserent` 承载**全部租房相关业务**（房源与求租是同一市场的供需两侧，订阅/匹配服务两者，审核服务两者）——领域内聚，一个业务模块；
- `core` 仅基础设施（跨领域公共能力），不承载任何业务；
- 后续若出现与租房无关的独立平台能力（如钉钉机器人长连接、定时任务调度），单独评估是否独立模块；
- 新代码约定：包根 `com.aliren.houserent.<子域>`（house/demand/subscribe/match/admin），依赖 `aliren-core`；测试放 `backend/test` 模块，包名跟随被测代码。

## 2. 数据表设计（schema.sql，6 张表）

| 表 | 说明 | 状态流转 |
|----|------|---------|
| `user` | 校友/管理员（钉钉 userid 唯一） | status: 1启用/0停用 |
| `house` | 房源 | audit_status: 0待审→1上架/2驳回；rack_status: 0在租→1已租出/2下架；feedback_answer: 0跳过/1找到新家/2暂无 |
| `demand` | 求租需求 | match_status: 0待匹配→1已匹配→2已成交 |
| `subscribe` | 订阅（找房源/找租客） | status: 0活跃/1暂停/2删除 |
| `report` | 举报（房源/用户） | status: 0待处理→1已处理 |
| `audit_log` | 审计日志（审核/下架/举报处理留痕） | — |

- 评价表（P2）不建；图片存 OSS/静态目录，表存 URL（JSON 数组）。
- 状态值一律 TINYINT，与实体 `Integer` 对应。

## 3. 接口清单（RESTful，统一响应 `{code,msg,data}`）

> 除 `POST /api/auth` 外全部需 `Authorization: Bearer <jwt>`。

### 3.1 auth / 用户（core）
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/auth` | 钉钉免登：code → 签发 JWT（返回 token + 用户信息） |

### 3.2 房源 house（houserent）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/houses` | 列表：仅已上架+在租；筛选 region/minRent/maxRent/label/petOk，按创建倒序 |
| GET | `/api/houses/{id}` | 详情：仅已上架可见；含房东信息（昵称/avatar） |
| POST | `/api/houses` | 发布（初始 待审核+在租）；`house_create_request` |
| GET | `/api/houses/mine` | 我的发布（全部状态，含审核/驳回原因） |
| POST | `/api/houses/{id}/off-rack` | 已租出下架：仅发布人/管理员 |
| POST | `/api/houses/{id}/feedback` | 轻问句回答：下架时选填（1=找到新家 2=暂无 0=跳过） |
| POST | `/api/houses/{id}/reports` | 举报房源（reason 必填） |

### 3.3 管理后台 admin（houserent）
| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/audit/pending` | 待审核队列（含房号 room_no，仅管理员） |
| POST | `/api/admin/audit/{houseId}` | 审核：通过/驳回（驳回必填原因）；通过后触发订阅/求租匹配（内部） |
| POST | `/api/admin/houses/{houseId}/off-rack` | 管理员下架 |
| GET | `/api/admin/reports` | 举报列表（status 过滤） |
| POST | `/api/admin/reports/{id}/handle` | 举报处理（result 必填，status→已处理，写 audit_log） |
| GET | `/api/admin/stats` | 数据看板（房源总数/待审核数/已租出数/今日新增） |

### 3.4 求租 demand（houserent）
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/demands` | 发布求租需求（初始 待匹配） |
| GET | `/api/demands` | 求租墙：待匹配+已匹配（不含已成交），按创建倒序 |
| GET | `/api/demands/mine` | 我的需求（全部状态） |
| GET | `/api/demands/{id}` | 需求详情 |
| POST | `/api/demands/{id}/withdraw` | 撤回（仅本人） |
| POST | `/api/demands/{id}/complete` | 标记已成交（仅本人） |

### 3.5 订阅 subscribe（houserent）
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/subscriptions` | 创建订阅：type（1=找房源 2=找租客）+ 自然语言原文（结构化条件可由前端传或后续 LLM 解析填充） |
| GET | `/api/subscriptions` | 我的订阅列表（不含已删除） |
| PUT | `/api/subscriptions/{id}` | 修改（条件/原文/免打扰 quietHours/暂停恢复：status 0/1） |
| DELETE | `/api/subscriptions/{id}` | 删除（status→2 软删） |

> 免打扰为订阅级字段（与钉钉方案一致），推送计数 push_count 在列表返回；推送历史/频控随 match/robot 阶段实现。

### 3.6 匹配 match（houserent）
| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/match/search` | 一句话找房：自然语言 → 3-5 套 + 匹配理由（LLM；失败降级为筛选兜底） |
| POST | `/api/match/subscriptions` | 订阅批量匹配：新房源上架时一次调用处理全部活跃订阅（内部触发，也可人工调用） |
| POST | `/api/match/demands` | 求租墙匹配：新房源上架时比对求租墙（内部触发） |

### 3.7 机器人/定时（骨架已落地，真实发送依赖钉钉凭证）
- `PushClient` 抽象（houserent/robot）：`sendGroupCard`（群卡片）/ `sendWorkNotice`（工作通知）；
  `PushClientStub` 缺省日志发送，`DingTalkPushClient` 配置 `aliren.robot.enabled=true` 后启用（真实 API 待凭证补全）
- `PublishOrchestrator`：审核通过编排（订阅/求租匹配 + 新上架卡片 + 私聊提醒）
- `schedule`：`@EnableScheduling`（`aliren.schedule.enabled` 开关）
  - 周五 19:00 精选周推（最新上架 3 套 + 本周新上架数）
  - 周一 10:00 安居故事（按 `feedback_answer=1` 统计上周找到新家校友数）

## 4. 安全设计

| 防线 | 实现 |
|------|------|
| 统一鉴权 | `AuthInterceptor` 拦截 `/api/**`（放行 `/api/auth`），JWT 解析写入 `UserContext` |
| 角色校验 | 管理员接口在 Service 层校验 `role==1`（服务端判定） |
| owner 校验 | 我的发布/撤回/下架等：`publisher_id == UserContext.requireUserId()`，否则 403 |
| 数据可见性 | 详情仅返回「已上架」；未上架/驳回对普通用户隐藏（房号 room_no 仅审核可见，不进公开 DTO） |
| 输入校验 | Jakarta Validation（@NotBlank/@NotNull/@DecimalMin），全局异常统一 400 |
| 限流（MVP） | 发布/举报做简单频控（按 userid 时间窗口，骨架） |
| 审计 | 审核/下架/举报处理写 `audit_log` |

## 5. LLM 匹配引擎设计

**决策：直接 LLM 批量匹配，无规则引擎。**（见产品文档 §6 / 钉钉方案 §4.4）

```
接口 MatchClient（可降级）：
  - 实现 A：通义千问（或钉钉 AI）—— 需配置 aliren.llm.api-key 等，条件装配
  - 实现 B：Stub —— 无凭证时启用，按区域/价格/标签简单过滤兜底，返回结构化结果
```

- 一句话找房：需求文本 + 候选房源（区域/价格预筛或全量，MVP 全量数百套）→ 单次调用 → JSON 输出 `[{houseId, reason}]` → 校验 schema → 返回
- 订阅批量匹配：新房源上架 → 全部活跃订阅拼入单 prompt → 输出命中订阅 ID + 理由（**1 次调用**）
- 求租墙匹配：新房源上架 → 求租墙（待匹配/已匹配）拼入单 prompt → 输出命中 demand ID + 理由
- 失败降级：调用异常 → 返回空结果/筛选兜底，**不阻断主流程**
- Prompt 结构隔离用户输入（防注入），输出按 JSON schema 校验

## 6. 配置（application.yml 新增项）

```yaml
aliren:
  llm:
    provider: stub            # stub | qwen（缺省 stub，配置 api-key 后启用 qwen）
    api-key: ${LLM_API_KEY:}
    model: qwen-max
    timeout-seconds: 10
  robot:
    enabled: false            # 钉钉推送（群卡片/工作通知），凭证就绪后置 true
    webhook: ${ROBOT_WEBHOOK:}
  schedule:
    enabled: true             # 定时任务（周五周推/周一故事）；真实推送依赖 robot
    weekly-pick-cron: "0 0 19 * * FRI"
    weekly-story-cron: "0 0 10 * * MON"
```

## 7. 部署

- `cd backend && mvn package` → `app/target/aliren-app-*-exec.jar`（可执行 fat jar，含全部模块）
- 运行：`java -jar aliren-app-0.1.0-SNAPSHOT-exec.jar`（环境变量注入 DB_PASSWORD/JWT_SECRET/DING_APP_KEY/DING_APP_SECRET/LLM_API_KEY）
- 轻量 ECS 2C2G + Docker 或 jar + systemd；Nginx 反代 + HTTPS
