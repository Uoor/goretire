# 校友安居 · 钉钉群里被 @ 后回复 —— 接入与改造方案

> 状态：待评审（确认后再写代码）
> 目标：让 aliren 的后端机器人，在钉钉群内被 @ 时**接收消息并回复**（双向对话），而不仅是单向推送。
> 关键决策：**新增独立机器人应用**（不动现有推送应用）；接收方式用 **Stream 模式**（WebSocket 长连接，无需公网回调域名）。

---

## 1. 背景与现状

### 1.1 现状（单向推送，无入站能力）

aliren 现有机器人只有"发"，没有"收"：

| 能力 | 实现 | 方向 |
|------|------|------|
| 群卡片（周推/故事/新上架） | `DingTalkPushClient.sendGroupCard/...` → 自定义机器人 **Webhook** | 只发 |
| 私聊工作通知 | `sendWorkNotice` → `topapi/message/corpconversation/asyncsend_v2`（企业应用 appKey/appSecret/agentId） | 只发 |

因此当前**无法**感知群里 @ 机器人的消息，也就无从回复。

### 1.2 现状的 PushClient 抽象

```
PushClient（接口）
├── DingTalkPushClient   # @ConditionalOnProperty(aliren.robot.enabled=true)
└── PushClientStub       # 缺省 Bean，日志模拟
```
新增 @ 回复链路应沿用同样的"接口 + 真实实现 + Stub"模式，不侵入现有推送。

## 3. 钉钉侧接入步骤（开放平台后台）

### 3.1 给应用开通机器人能力

在钉钉开发者后台进入该应用 → 添加「**机器人**」能力：

1. 勾选并添加机器人 → 生成 **`robotCode`**（机器人编码，独立于 AgentId，回复时要用）。
2. 在机器人配置里选择「**消息接收模式**」→ **Stream 模式**（WebSocket）。
3. 将机器人**添加到目标群**（可通过 `dws chat group members add-bot --robot-code ... --id ...`，或群里手动添加）。

### 3.2 接收 @ 消息（Stream 模式）

- 用 `DingStream`（WebSocket 长连接）以应用 `appKey/appSecret` 建立客户端凭据连接。
- **订阅主题：`RobotCallback`**。
- 有人 @ 机器人时，回调事件 payload 关键字段：

| 字段 | 含义 | 回复时用途 |
|------|------|-----------|
| `openConversationId` | 群开放会话 ID | 回发目标群 |
| `robotCode` | 机器人编码 | 回发鉴权 |
| `senderStaffId` | 提问人 userId | @ 回对方 |
| `senderNick` | 提问人昵称 | 展示 |
| `text` | 用户 @ 后输入的内容 | 解析指令 |
| `msgId` | 消息 ID | 幂等/去重 |
| `msgtype` / `conversationType(=2)` | 类型校验 | 群聊过滤 |

### 3.3 回复到群里

调用 IM 机器人发群消息接口（企业内部应用机器人）：

```
POST /v1.0/im/robot/groupMessages/send
{
  "robotCode": "<robotCode>",
  "openConversationId": "<openConversationId>",
  "msgKey": "sampleText",
  "msgParam": "{\"content\":\"回复内容\"}"
}
```

- **@ 回提问人**：`msgParam` 内带 at 信息（如 `atDingtalkIds`/`atUserIds`）。字段级细节以开放平台当前文档为准（见 §6 待确认）。
- `msgKey` 模板：`sampleText`（纯文本）、`sampleMarkdown`（富文本，可带标题）等。

## 4. aliren 后端改造方案

### 4.1 新增抽象（沿用 Stub 模式）

新增包 `com.aliren.houserent.robot.reply`：

```
RobotReplyClient（接口）
├── StreamRobotReplyClient     # @ConditionalOnProperty(aliren.robot.reply.mode=stream, enabled=true)
└── RobotReplyClientStub       # 缺省 Bean，日志模拟
```

接口设计（示意）：

```java
public interface RobotReplyClient {
    /** 启动接收（Stream 长连接 / 回调注册）。服务启动后由配置开关触发。 */
    void start();
    /** 处理群里 @ 消息并回复 */
    void handleGroupMention(GroupMentionMessage msg);
}
```

### 4.2 Stream 接收实现（`StreamRobotReplyClient`）

- 用 `DingStream` 客户端 + `AppCredential(appKey, appSecret)`。
- 注册 `RobotCallback` 订阅监听器，收到 `BotCallbackDataModel` 后：
  1. 校验 `conversationType == 2`（群聊），提取 `openConversationId`、`senderStaffId`、`text`。
  2. 去重（按 `msgId`，短窗口内存 Set 或 Redis）。
  3. 解析指令 → 调 `MatchService`（一句话找房 / 订阅匹配）或固定话术。
  4. 调 `/v1.0/im/robot/groupMessages/send` 把结果发回群里。
- 长连接需**常驻 + 断线重连**（与 `aliren.schedule` 无关，独立生命周期；可用 `@PostConstruct` + 后台线程）。

### 4.3 配置项（走 `${ENV:default}`，敏感项占位）

`application.yml` 新增（前缀 `aliren.robot.reply`）：

```yaml
aliren:
  robot:
    reply:
      enabled: ${DING_REPLY_ENABLED:false}        # 总开关，默认关（fail-closed）
      mode: ${DING_REPLY_MODE:stream}             # stream | callback
      app-key: ${DING_REPLY_APP_KEY:}
      app-secret: ${DING_REPLY_APP_SECRET:}       # 敏感，仅 env 注入
      robot-code: ${DING_REPLY_ROBOT_CODE:}       # 开通机器人能力后获得
      agent-id: ${DING_REPLY_AGENT_ID:4631726481}
```

`.env`（ECS）新增：

```bash
# ---- 群里 @ 回复（专用机器人，与推送应用分开）----
DING_REPLY_ENABLED=true
DING_REPLY_MODE=stream
DING_REPLY_APP_KEY=ding4xccwzeyg83iij2u
DING_REPLY_APP_SECRET=<由部署者填写，不入库>
DING_REPLY_ROBOT_CODE=ding4xccwzeyg83iij2u
DING_REPLY_AGENT_ID=4631726481
```

> 说明：`DING_REPLY_APP_SECRET` 由部署者以环境变量注入 `.env`（`.env` 已在服务器 gitignore 清单或独立管理），**不写入仓库**。`robotCode` 在开通机器人能力前暂缺，功能保持关闭。

### 4.4 复用现有能力

- 回复内容生成复用 `MatchService`（一句话找房 / 订阅匹配），与现有「订阅/求租匹配」共用同一套降级逻辑。
- 出错兜底：匹配异常 / 无结果时，回复固定引导话术（如"换个说法试试 / 联系管理员"）。

## 5. 部署与验证

1. 后端构建：`mvn package -DskipTests`（`app/target/aliren-app-0.1.0-SNAPSHOT-exec.jar`）。
2. ECS：`./scripts/deploy-remote.sh --skip-build` 前先更新 `.env` 新增项，再重启。
3. 验证：
   - 群内 @ 机器人发"找 3 号线附近一居室" → 应收到机器人回复（含匹配结果）。
   - 确认现有群卡片 / 工作通知推送不受影响（回归）。
   - 重启后 Stream 长连接自动恢复（断线重连日志）。
