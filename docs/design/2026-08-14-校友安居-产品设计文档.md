# 「校友安居」产品设计文档

> 社群：【阿里人·一起提前退休】
> 项目：校友安居 —— 只属于阿里/蚂蚁人的可信租房网络
> 日期：2026-08-14
> 状态：v1.2 定稿（2026-08-14 最终评审：MVP 补求租墙、成交机制重构为已租出下架、LLM 批量匹配、通勤房东填写、知识库群问答活水、收藏/互评后置）

---

## 1. 背景与目标

### 1.1 背景

社群现有 6000+ 校友，围绕"提前退休"主题运营金融理财、香港身份、AI 等模块。租房是社群成员的高频真实需求：阿里/蚂蚁在职与离职校友在大厂园区（杭州/北京/上海/深圳）间流动频繁，换组、外派、离职、转城市都伴随找房/转租/合租。

当前市场痛点：中介平台信息真假难辨、骚扰电话不断；微信群/豆瓣租房组信息淹没、无信任背书。社群完全有机会做一个**只属于自己的租房网络**。

### 1.2 目标

1. **真正撮合交易**：让校友的房源被 6000 个优质租客看到，让校友租客最快找到真房源，从看到、到聊、到成交全程在可信环境内完成。
2. **加强社群品牌**：把社群"互助、真实、免费"的价值观产品化，安居成为校友退休/换城市时互相托底的生活基础设施。
3. **体现差异化**：圈层信用是抄不走的——"只属于阿里/蚂蚁人"本身就是最大差异化。

### 1.3 价值主张

> **「校友安居」= 一个只属于阿里/蚂蚁人的可信租房网络：让房东愿意直租给校友，让租客最快找到真房源，让每一次成交都在为社群品牌加分。**

## 2. 目标用户与场景

| 用户 | 典型场景 | 核心诉求 |
|------|---------|---------|
| **在职校友（租客）** | 入职/换组/外派到杭州滨江、北京望京等园区 | 快速找到通勤近、真房源、不被坑的房子 |
| **离职校友（租客）** | 换城市发展、提前退休迁居 | 了解区域行情，找到性价比高的房子 |
| **校友房东/二房东** | 有房出租、原房转租、招室友 | 租给靠谱的人，不被中介抽成，快速成交 |
| **运营（管理员）** | 审核房源、维护信誉分、产出周报 | 高效把关，维持社区纯净 |

**核心场景故事（示例）：**

> 小林从北京调岗到杭州，打开钉钉工作台 →「校友安居」→ 输入"西溪附近 6000 以内两居、能养猫"→ AI 返回 3 套房源并附匹配理由 → 钉钉内联系房东（身份互见）→ 看房成交 → 互相评价。

## 3. 产品形态

### 3.1 载体与入口

```
钉钉 App
 ├─ 工作台 →「校友安居」应用图标（组织内成员可见）
 │     └─ 点击进入 H5 微应用（钉钉免登，校友身份即登录）
 ├─ 群「校友安居」→ 机器人推送卡片（新上架/精选周推/租金周报）
 │     └─ 点击卡片 → 跳回 H5 对应房源详情
 └─ 消息 → 匹配提醒（机器人私聊："你的求租需求有新房源了"）
```

形态一句话：**工作台 H5 应用是"店"，子群机器人是"喇叭"，消息提醒是"敲门"。**

### 3.2 前置条件（组织基建）

1. **社群自有钉钉组织**：离职校友不在阿里/蚂蚁企业通讯录，需由社群自建组织、邀请校友入编，实现全员免登。
2. **创建组织应用**：在钉钉开放平台创建企业内部 H5 应用「校友安居」，配置工作台入口。
3. **开通能力**：机器人（群消息）、免登（身份认证）、多维表格（数据层）、知识库（内容层）。

### 3.3 产品地图

```
┌─ 底部导航 5 个 Tab ────────────────────────────────┐
│                                                    │
│  [首页]    [求租]    [订阅]     [发布]      [我的]   │
│  房源广场  求租需求墙  订阅中心    发布房源    个人中心 │
│  ├ 搜索框  ├ 发需求  ├ 创建订阅   ├ 表单      ├ 我的发布(状态)
│  ├ 筛选(区域/ ├ 我的需求 ├ 订阅列表   ├ AI辅助    ├ 我的评价(P2)
│  │  价格/户型/ ├ 匹配结果 ├ 推送历史   │ 定价参考  ├ 我的评价
│  │  标签/通勤) └ 匹配提醒 ├ 免打扰设置  └ 提交审核  ├ 信誉分
│  ├ 房源卡片流   (新上架自动匹配)              └ 设置
│  └ 周报入口                                    │
└──────────────────────────────────────────────────┘

独立页面：
 ├ 📄 房源详情（图集/价格明细/房东信息/联系/举报）
 ├ 📊 租金周报（区域均价走势 + 成交故事）
 ├ 📖 避坑指南（知识库：合同模板/押金清单/骗局案例）
 └ 🛡 管理员后台（审核队列/信誉分/举报处理）
```

## 4. 功能设计（逐页）

### 4.1 首页 · 房源广场

**首屏布局：**

```
┌────────────────────────────────┐
│ 🔍 说人话找房：西溪附近 6000 以内两居 │
├────────────────────────────────┤
│ 🏠 西溪八方城 89㎡ 两居整租          │
│ 月租 5800 │ 押一付三 │ 可养猫        │
│ 🏷️ 房东直租 ✅已核实               │
│ 🚇 西溪园区 15 分钟                 │
│        [ 钉钉内联系房东 ]           │
└────────────────────────────────┘
```

*注：信誉分星级展示为后续版本内容，MVP 阶段内部记账、不在卡片公开。*

**房源卡片仅 6 要素**（卡片即决策单元，不堆信息）：

| 要素 | 说明 |
|------|------|
| 价格/户型 | 月租 + 面积 + 居室 + 整租/合租 |
| 押付方式 | 押一付一/押一付三/押二付一等 |
| 标签 | 房东直租 / 校友转租 / 合租拼室友（不同标签不同信任权重） |
| 已核实标 | ✅ 管理员审核通过标识 |
| 通勤 | 到最近阿里/蚂蚁园区的时间（**房东发布时填写**，参考值） |
| 联系按钮 | 钉钉内联系房东（身份互见） |

> 信誉分（星级展示）为后续版本内容，MVP 不公开。

**筛选条件**：区域（杭州滨江/西溪、北京望京/西二旗、上海、深圳）、价格区间、户型、标签（直租/转租/合租）、通勤时间、可养宠、新上架。

### 4.2 房源详情

- 图集（最多 9 张，首图为封面）
- 价格明细：月租、押付、水电网物业是否含
- 位置：小区/楼栋（**公开展示仅到小区**，房号仅审核可见），通勤时间
- 房东信息：校友身份、信誉分（**P2 公开**，MVP 内部记账）
- 操作：钉钉内联系、举报（收藏后置 P2）
- 附送：避坑指南快捷入口（合同模板/押金清单）

### 4.3 发布房源（3 分钟完成）

```
第1步：拍照（最多9张，第一张做主图）
第2步：选小区 + 填房号（房号仅审核可见，公开展示只到小区）
      └→ AI 自动带出：区域、参考租金区间（来自周报数据）
第3步：选户型/面积/租金/押付/租期 + 选标签（房东直租/转租/合租）
第4步：填通勤时间（参考值，如"到西溪园区约 15 分钟"，房东自行填写）
第5步：一句话描述（可空，如"房东自住刚搬走，家具全"）
第6步：提交 → 「✅ 已提交审核，预计 2 小时内上架」
```

**通勤时间口径（已拍板）**：MVP 由房东发布时人工填写（参考值，审核时可校准）；不接地图 API，地图服务整体留到 P2 与「地图找房」一起接入。

**房东价值感设计**：填完地址自动带出参考租金区间（来自周报数据）——房东立刻知道自己定价是否合理，感觉"这是专业工具，不是发帖板"。

### 4.4 找房与求租（两个场景）

> 两个独立场景，入口不同：首页搜索框 = **即时找房**（有房源可看时）；求租 Tab = **发需求进墙**（暂时没合适的，等新房源推送）。

#### 4.4.1 一句话找房（即时检索）

**输入示例**：*"预算 6000 以内，西溪附近，能养猫，最好有车位"*

**AI 返回 3-5 套 + 匹配理由**：
```
1. 西溪八方城 89㎡ 两居 5800  ← 近西溪园区15分钟，可养猫，带车位，超预算-200
2. 西溪蝶园 75㎡ 两居 5500   ← 可养猫，无车位，通勤20分钟
3. 蒋村 60㎡ 一居 4800       ← 可养猫，小区外有公共车位
```

#### 4.4.2 求租需求（求租墙）

- **触发时机**：即时找房没合适房源时，一键"把需求挂上求租墙"
- **机制**：新房源上架 → LLM 比对求租墙 → 匹配成功即私聊提醒
- **需求表单字段**：预算区间、目标区域、户型、入住时间、租期、特殊要求（宠物/车位/楼层/朝向）、一句话描述
- 需求状态：待匹配 / 已匹配 / 已成交（发布人可手动撤回）

> **求租需求 vs 订阅**：求租需求 = 一次性发起，进墙等待；订阅 = 持续关注某类内容，长期被推。两者并存、互不替代。

### 4.5 订阅中心（自然语言订阅 · 双向）

**设计目标**：突出订阅功能价值、强提醒用户——"订阅你想要的，新房源主动找你"。

**入口**：底部导航独立 Tab「订阅」+ 首页顶部引导 banner「🔔 订阅你想要的，新房源主动找你」。

**创建订阅（自然语言，AI 解析）**：

```
租客视角：输入"西溪附近 6000 以内两居，能养猫"
          → AI 解析为结构化条件（区域/价格/户型/可养宠）→ 订阅生效
房东视角：输入"有西溪两居 5000-6000 想租出去"
          → AI 解析 → 关注该类求租需求，新租客需求出现即通知
```

**双向订阅**：
- 租客订阅：关注新房源（按区域/价格/户型/特殊要求）
- 房东订阅：关注新求租需求（按区域/租金区间/户型）

**匹配与推送（实时 + 防骚扰 + 批量）**：
- 新房源/新需求上架 → LLM 匹配引擎**一次调用处理全部活跃订阅**（订阅列表拼入单个 prompt，输出命中的订阅 ID + 理由）——上新 = 1 次调用，成本可控
- 高置信度才推 → 机器人私聊卡片
- 推送附命中理由（延续"匹配理由"设计语言），用户看到"为什么推给我"
- 防骚扰约束：每日推送上限 + 免打扰时段设置

**订阅管理**：订阅列表（暂停/修改条件/删除）、推送历史、免打扰时段。

**数据价值（需求雷达）**：订阅数据反哺运营——看大家都在订阅什么 → 引导房东补供给、租金周报选题。

### 4.6 租金周报

- 区域均价走势（按周/月，数据来源：房源库成交与挂牌记录）
- 覆盖区域：杭州（滨江/西溪/蒋村等）、北京（望京/西二旗等）、上海、深圳园区周边
- 附「本周成交故事」：如"本周 3 位校友通过安居找到新家"
- 作为公共品免费分享，校友转发即品牌出圈

### 4.7 避坑指南（知识库）

- 合同模板（可下载）
- 押金避坑清单（押金退还、扣款条款）
- 常见骗局案例（假房东、二房东跑路、租房贷）
- 区域攻略（各园区周边居住指南：通勤/生活配套/口碑小区）

**内容来源（租房经验问答，已确认极简版）**：
- 群友在「校友安居」子群自然提问、互答（纯群内交流，零开发）
- 群内 @机器人 可从知识库检索快速应答（选做，复用 LLM 能力）
- **管理员把群内优质问答手动整理进本知识库**（直接编辑 wiki，零开发）
- 定位：知识库是问答的沉淀处，问答是知识库的活水——运营投入，非开发投入

### 4.8 我的（个人中心）

- 我的发布：状态跟踪（待审核/已上架/**已租出**/已驳回/被举报）+ **一键「已租出，下架」**（下架时选填轻问句"在安居找到新家了吗？"）
- 我的需求：求租墙需求管理（撤回/完成）
- 我的订阅：订阅管理入口
- 收藏 / 评价 / 信誉分：**P2 后置**（MVP 不做，保持极简）

### 4.9 管理员后台

- 审核队列：新发布房源 → 通过/驳回（驳回需填原因）
- 信誉分管理：举报处理、扣分、拉黑
- 数据看板：房源量、成交数、区域分布
- 周报数据导出

## 5. 信任与审核机制

| 机制 | 设计 |
|------|------|
| **身份认证** | 钉钉免登即校友身份；离职校友经社群组织入编后可用 |
| **审核上架** | 所有房源经管理员审核后上架（承诺 2 小时内），通过后打「✅已核实」标 |
| **房源类型标签** | 房东直租 / 校友转租 / 合租拼室友，不同标签信任权重不同 |
| **避坑随卡** | 每张房源卡片附合同模板与押金清单入口 |
| **举报与信誉分** | 群友可举报；被多次举报者禁发（MVP）；**信誉分与成交互评 P2 后置**，优质房东房源置顶随之后置 |
| **透明公示** | 处理结果对相关方可见，规则公开 |

## 6. AI 能力设计

**核心决策：匹配引擎直接上 LLM（不写规则引擎）。** 房源量级（数百套）远小于 LLM 上下文上限，候选房源直接拼入 prompt，一次调用同时完成匹配与理由生成。同一个 LLM 匹配服务统一服务「一句话找房」「订阅匹配」「求租墙匹配」。

| 能力 | 触发方式 | 输出 |
|------|---------|------|
| 一句话找房 | 首页搜索框自然语言输入 | LLM 从房源库选出 3-5 套 + 每条匹配理由 |
| 定价参考 | 发布房源时 | 区域参考租金区间（可走 LLM 或静态区间表） |
| 订阅创建解析 | 创建订阅时 | 自然语言 → 结构化条件（LLM 解析并缓存） |
| 订阅实时匹配 | 新房源/新需求上架时 | LLM 比对活跃订阅，高置信度即推（附命中理由） |
| 求租墙匹配 | 新房源入库时 | LLM 比对求租墙，匹配即私聊提醒 |
| 精选周推 | 每周五 | 本周精选 3 套（LLM 按相关性/新上架挑选；"热度"数据 MVP 阶段以浏览量为准，P2 可加） |

## 8. 数据模型（多维表格）

### 8.1 房源表（核心表）

| 字段 | 类型 | 说明 |
|------|------|------|
| 房源ID | 文本 | 自动 |
| 标题/封面图 | 附件/文本 | 首图 |
| 小区/地址 | 文本 | 选填后 AI 补全区域 |
| 区域/城市 | 单选 | 杭州滨江/西溪、北京望京/西二旗、上海、深圳… |
| 户型/面积 | 文本/数字 | 如 2室1厅 / 89 |
| 月租/押付方式 | 数字/单选 | 押一付一、押一付三… |
| 标签 | 单选 | 房东直租/校友转租/合租拼室友 |
| 可养宠 | 布尔 | — |
| 描述 | 长文本 | 可空 |
| 通勤时间 | 文本 | 房东发布时填写（参考值） |
| 审核状态 | 单选 | 待审核/已上架/已驳回 |
| 审核人/审核时间 | 人员/时间 | — |
| 发布人 | 人员 | 校友身份 |
| 举报次数 | 数字 | 关联举报表 |
| 下架状态 | 单选 | 在租中/已租出/已下架（发布人一键下架） |
| 轻问句回答 | 单选 | 下架时选填："在安居找到新家了吗？"（是/否/跳过） |
| 信誉分 | 数字 | P2 字段（MVP 可空） |

## 9. MVP 范围（第一版做与不做）

### 做（完整版 MVP，全部同期上线）

**匹配引擎直接上 LLM（不写规则引擎）**，订阅与一句话找房因此不再依赖数据积累，提前进入 MVP。

1. 发布房源（表单 + AI 定价参考）
2. 管理员审核上架 + 「✅已核实」标
3. 首页房源流 + 搜索 + 筛选
4. 一句话找房（LLM 直接匹配）
5. 求租需求 / 求租墙（新房源自动比对 + 私聊提醒）
6. 订阅中心（自然语言创建 + LLM 实时匹配推送 + 订阅管理）
7. 机器人推送（新上架卡片 + 精选周推 + 安居故事）
8. 我的发布（状态跟踪 + 一键「已租出，下架」+ 轻问句）

> MVP 即完整闭环：发布 → 审核 → 展示/推送 → 一句话找房/求租墙/订阅匹配 → 联系 → 已租出下架。

### 不做（后置）

| 项 | 原因 |
|----|------|
| 地图找房 | 列表+筛选够用，后置 |
| 在线签约/支付 | 涉及资金与法务，风险高，后置 |
| 收藏 | MVP 不做，保持极简，P2 |
| 成交互评 / 信誉分公开 / 评价墙 | 避免商业化观感；MVP 仅"已租出下架 + 轻问句"保真实，P2 再深化信任机制 |
| 对话式群内检索 | MVP 用 H5 内搜索，后续可加 |
| 通勤估算（增强版） | MVP 只给单值，后续可加地图路径 |

## 13. 风险与对策

| 风险 | 对策 |
|------|------|
| 房源供给不足（冷启动） | 运营种子房源 + 邀请制房东入驻 + 优质房东激励 |
| 审核压力 | 值班轮岗 + 标准审核 checklist + 后续 OA 自动化 |
| 虚假信息/骗局 | 身份认证 + 审核上架 + 举报机制 + 避坑指南教育 |
| 组织外校友认证 | 社群自建组织 + 人工邀请入编 |
| 与中介利益冲突 | 明确公约"不收费、不中介"，房源限校友发布 |
| 数据量不足致 AI 匹配弱 | 直接 LLM 匹配本身不依赖数据量；冷启动时提示语中附「暂无更多房源」降级文案 |
| **LLM 依赖/可用性** | **匹配服务做超时降级（失败则提示稍后重试）+ 简单兜底（按区域/价格过滤）** |
| **LLM 成本** | **按调用量计费（每日几十次，量级可忽略）；加缓存与频率控制** |
