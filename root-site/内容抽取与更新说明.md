# 内容抽取与更新说明

## 官网角色

官网现阶段是“社区前厅”，不是知识库目录，也不是独立内容平台。

它需要同时提供四种理由：

- 值得相信：能看到社区起源、公开规则和信息边界。
- 值得回来：能快速知道最近群里与外部在发生什么。
- 值得使用：有轻量工具和直接可读的结论。
- 值得连接：知道怎样进群、找人、分享资源或谈合作。

## 页面内容从哪里来

### 群聊摘要

输入：总群、A股群、AI群的公开可用聊天记录。

处理：

1. 只抽取主题、共识、分歧和可继续讨论的问题。
2. 删除姓名、头像、联系方式、公司内部信息和可识别细节。
3. 合并相似话题，避免把原始聊天直接搬到官网。
4. 人工确认后更新到 `assets/content-data.js` 的 `groups`。
5. 页面展示更新时间，不展示未经核验的群消息量。

建议频率：工作日午间一次、晚间一次。首页只留三个群和每群三个重点。

### 每日信号

输入：现有机器人、公开知识库、可信外部信息源。

处理：

1. 每条必须保留来源、时间和有效期。
2. 把事实与群友观点分开。
3. 去重后只选最多三条：一条变化、一条提醒、一条可行动信息。
4. 涉及市场的信息只做事实和学习交流，不做收益承诺或个股建议。
5. 人工确认后更新 `signals`。

建议频率：按机器人事件实时入池，每天人工精选后上首页。

### 长期内容

优先把现有知识库抽成“一个结论 + 一个工具 + 一个资料入口”：

- 房产框架 → 租/买/卖三问工具。
- 房产指标字典 → 城市、板块、小区比较卡。
- 离职 SOP → 分阶段清单。
- AI 内容 → 岗位工作流和权限边界。
- 投资复盘 → 事件日历、风险问题和群友复盘。
- 身份/港卡资料 → 场景、成本、维护三项比较。
- 资源福利 → 来源、适用人群、有效期、关系说明四字段。

## 自动化字段

`assets/content-data.js` 是当前静态数据层。后续抓取服务只需要稳定输出：

- `updatedAt`
- `groups[]`：id、群名、摘要、三个主题
- `signals[]`：时间、标题、说明、来源
- `question`
- `resources[]`：类型、标题、说明、有效期、关系披露

建议发布流：采集 → 去重 → 匿名化 → 人工审核 → 生成数据文件 → 自动测试 → 发布。

## 不能自动公开的内容

- 原始群聊全文、成员姓名、头像、手机号和联系方式。
- 公司内部材料、未公开业务信息和私人经历细节。
- 未核验的合作权益、房源、岗位和活动。
- 金融产品销售、收益承诺或以社区名义给出的投资建议。

## 当前仍需补齐

- 小助理二维码或独立联系页。
- 公众号、视频号和微信群入口。
- 各机器人可公开的准确名称、来源和推送节奏。
- 合作资源的提交表单与审核负责人。
- 群聊摘要的授权范围和人工审核人。
